# Open Ephys 1.0.3 Message Length Crash Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent a broadcast message longer than 512 characters from crashing Open Ephys while preserving the existing 512-character event limit.

**Architecture:** Correct the ignored immutable `juce::String::dropLastCharacters` return value inside Message Center and stop safely if event construction still fails. Exercise the behavior through `MessageCenter::processBlock` so the regression test covers serialized TEXT-event output rather than a new helper API.

**Tech Stack:** C++17, JUCE 8, GoogleTest, CMake, Ninja.

## Global Constraints

- Baseline is official `v1.0.2`, commit `c91afebcfb0678a667fb93f6312ed33c56ec640f`.
- Plugin API remains `10`.
- The maximum broadcast TEXT-event length remains exactly 512 characters.
- No HTTP route, visible GUI behavior, plugin ABI, or configuration format changes.
- Scope is limited to upstream issue #695 and upstream Message Center fix `3e4f98ca`.
- GenericProcessor hardening commit `fc6d2464` is a separate PR and release candidate.
- The production fix already exists on official `development`; do not submit duplicate production code upstream.

**Interfaces:**
- Consumes: `MessageCenter::broadcastMessage`, `GenericProcessor::processBlock`, `TextEvent::deserialize`.
- Produces: one serialized TEXT event whose content is limited to 512 characters, or no event if construction fails.

- [ ] **Step 1: Add a test helper and failing boundary tests**

Append the following helper and tests to `Tests/Processors/MessageCenterTests.cpp`:

```cpp
static TextEventPtr processBroadcast (MessageCenter& messageCenter, const String& text)
{
    messageCenter.addSpecialProcessorChannels();
    messageCenter.broadcastMessage (text, 100);

    AudioBuffer<float> audioBuffer (1, 1);
    audioBuffer.clear();
    MidiBuffer eventBuffer;
    messageCenter.processBlock (audioBuffer, eventBuffer);

    if (eventBuffer.getNumEvents() != 1)
        return nullptr;

    const auto metadata = *eventBuffer.begin();
    return TextEvent::deserialize (metadata.data, messageCenter.getMessageChannel());
}

TEST_F (MessageCenterTests, BroadcastAtLimitIsPreserved)
{
    const String input = String::repeatedString ("a", 512);
    const auto event = processBroadcast (*messageCenter, input);
    ASSERT_NE (event, nullptr);
    EXPECT_EQ (event->getText(), input);
}

TEST_F (MessageCenterTests, BroadcastOverLimitIsTruncatedSafely)
{
    const String input = String::repeatedString ("b", 514);
    const auto event = processBroadcast (*messageCenter, input);
    ASSERT_NE (event, nullptr);
    EXPECT_EQ (event->getText().length(), 512);
    EXPECT_EQ (event->getText(), input.substring (0, 512));
}
```

- [ ] **Step 2: Run only the new regression tests and confirm the old code fails**

- [ ] **Step 3: Apply the minimal upstream-equivalent Message Center fix**

Replace the truncation/event-creation block in `Source/Processors/MessageCenter/MessageCenter.cpp` with:

```cpp
if (eventString.length() > MAX_MSG_LENGTH)
{
    CoreServices::sendStatusMessage ("Broadcast message length exceeds maximum; truncating message to "
                                     + String (MAX_MSG_LENGTH) + " characters.");
    eventString = eventString.dropLastCharacters (eventString.length() - MAX_MSG_LENGTH);
}

TextEventPtr event = TextEvent::createTextEvent (eventChannels[0],
                                                 message.systemTimeMilliseconds,
                                                 eventString);

if (event == nullptr)
{
    LOGE ("Message Center: failed to create event for message: ", eventString);
    messageQueue.pop();
    continue;
}
```

Do not modify `GenericProcessor::addEvent` in this PR.
